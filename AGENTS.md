# Coding Rules

- Make the smallest possible change required to complete the task.
- Do not refactor unrelated code.
- Do not rename existing variables, functions, classes, or files unless explicitly requested.
- Do not rewrite existing comments unless explicitly requested.
- Do not reorganize code structure unless necessary.
- Do not introduce new abstractions, helper functions, classes, or design patterns unless required.
- Preserve the existing coding style and structure.
- Prefer modifying 1-5 lines over rewriting an entire function.
- Do not "clean up" working code unless the task specifically asks for cleanup.
- If the requested change can be made locally, keep it local.
- Simulation logic and architecture decisions must not be changed without explicit instruction.
- Never modify code outside the scope of the user's request unless it is required to make the requested change work.
